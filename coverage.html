    What is protected¶

    This page explains what AI Firewall protects, what it does when it finds private data, and what it does not cover.

    What AI Firewall looks for¶

    AI Firewall reads your request on your computer, before it goes to the AI tool. It can find 32 kinds of private data. 20 of them are on by default. Examples:

    • names and contact details
    • ID numbers and bank card numbers
    • passwords and secret keys
    • other personal or confidential details

    The Protection screen shows the full list, in four groups: People, Credentials, Financial and Government identity.

    It also checks:

    • Files: Word, Excel, PowerPoint and PDF.
    • Images and screenshots: it reads the text inside the picture.

    What it does when it finds something¶

    There are three choices. Each one is a mode.

    Mode (top bar) Name on the Protection screen What happens When it fits
    Monitor Record only The request is sent as you typed it, and a log entry shows what left your computer. The one exception is machine secrets such as API keys: those are replaced by default. The first days, to see what is really being sent. This is the default for new teams.
    Mask Replace (recommended) Private details are swapped for placeholders before sending. They are put back in the answer you read. The AI can still help you. A detection is replaced only when the firewall is sure enough (see below). Everyday use.
    Protect Block A request is not sent when the firewall is sure enough (see below) that it holds private data. You see what was found. You can edit your prompt and try again. When private data must never leave your computer.

    How sure is "sure enough"? Each finding has a confidence score, and two checks use it differently:

    • Names, organisations and addresses (found by the language model). A finding below the model's cutoff is dropped: it is not replaced and it is not recorded as a detection. The cutoff is set for each kind of finding. The model ScienceSoft ships is tuned to lean towards catching names, so a name it is only fairly sure about is still replaced. Your IT team can change the cutoff for each kind.
    • Numbers and codes found by patterns (cards, account numbers, ID numbers, e-mail addresses). In Replace and Block a weak match, for example an ordinary word that looks like a bank code, is not replaced and does not block a request. It stays in the record of what was found, and the log on this computer shows it. In Record only every match is recorded.

    You cannot change this on your computer. Ask your IT team what is set.

    Detection of passwords and other credentials is always on. It cannot be switched off. What happens to a credential still depends on the mode: it is blocked in Block mode, replaced in Replace mode, and recorded in Record only mode (except machine secrets, which are replaced).

    Because Monitor is the default, a new team is not yet replacing most private data. Ask your IT team which mode is set for you.

    Who chooses the mode¶

    Your company decides. Your IT team sets the rules for all computers. You cannot change the mode or the list of data types in the app. The Protection screen shows them, so you know what protects you, and shows how long ago your rules were last updated. If the computer is not connected to a company, the app uses the default: Record only.

    What you can change on your own computer:

    • Company patterns: your own patterns for things only your company would recognise. They stay on your computer.
    • The detection model and the languages for reading text in images (Detection engine screen).
    • Notifications, and whether AI Firewall starts with your computer.
    • Command-line tools: whether Claude Code, Codex or Kimi Code go through the firewall (see below).

    Where it works¶

    Where you use AI Covered?
    Web browsers: Chrome, Edge, Safari Yes, automatically
    Firefox Yes, if it is set to "Use system proxy settings"
    Desktop apps built on web technology, such as Claude Desktop Yes, automatically
    Claude Code Yes, after it is turned on
    Codex Yes, after it is turned on
    Kimi Code Yes, after it is turned on

    You do not need to set anything up for Claude Desktop. It is covered automatically.

    Command-line tools are off until someone turns them on. These tools do not follow the system proxy setting, so AI Firewall has to change each tool's own settings. It does not do that unless you ask, or your IT team asks. Until then, the tool's requests are not checked.

    • To turn a tool on yourself, open Device & coverage and select Connect a command-line tool.
    • Your IT team can also turn tools on for the whole company.
    • Turning protection off, or uninstalling, puts the tool's settings back.
    • Start a new session of the tool afterwards. A session that was already running keeps its old settings.
    • Claude Code and Kimi Code cannot both be covered at once.
    • On Device & coverage, the row Command-line tools shows if they are covered.

    At the time of writing, AI Firewall covers 38 AI services in the browser, including Claude, ChatGPT, Gemini, Microsoft Copilot, GitHub Copilot, Perplexity and Grok. The list grows with new versions.

    What is checked inside a request¶

    • What you type, and what your AI tools read back (for example, files that Claude Code reads for you).
    • Images and screenshots (text is read on your computer).
    • Documents: Word, Excel, PowerPoint, PDF and OpenDocument files, and .zip files one level deep. In Replace mode, a cleaned copy is sent instead of the original.
    • A file that cannot be read (encrypted, damaged, unknown format, or a zip inside a zip) is recorded as not checked, with the reason. By default it is still sent. Your IT team can choose to refuse such files instead.

    What is NOT covered¶

    We state this clearly, so you never find out by accident.

    • Command-line tools that are not turned on, and all other command-line tools, including curl and your own scripts. They send requests straight to AI services.
    • Aider, Visual Studio Code, Cursor and Continue. AI Firewall does not set these up. Cursor's built-in browser side is covered like any web-based app.
    • JetBrains AI Assistant. Not covered today.
    • Documents attached in Microsoft 365 Copilot. They are stored in your company's OneDrive and read there, so they never pass through the firewall. They are not checked. Each upload is recorded as "An attachment's contents were not inspected". Images attached in Copilot are checked. Your IT team can choose to block these uploads.
    • Apps that pin their own certificate. AI Firewall cannot read their traffic, and the connection fails instead of being skipped.
    • Some VPN clients. A VPN can take over the network setting. When that happens, the agent records it and your IT team can see it.
    • Anything encrypted by the app itself before it reaches the network.
    • Any AI service not named in the list. There is no catch-all.

    An AI tool that is not named in this guide is not protected.

    Known side effect: Microsoft Teams and Outlook¶

    To cover Microsoft 365 Copilot, AI Firewall also inspects graph.microsoft.com. The Teams, Outlook and Office desktop apps pin their certificate for this address. On a computer that has them, they may fail to sign in or send messages while protection is on. If that happens, tell your IT team. Turning protection off restores them.

    When AI Firewall is not running¶

    The app can be closed, for example with Quit in the tray menu. When it is closed, protection stops.

    • Windows with the system guard, and macOS installed from the .pkg: AI services it covers become unavailable instead of being reached without protection. Your IT team can grant an exception. On macOS this holds for the network connections the Mac had at install time. A connection added later, such as a USB adapter, can reach AI services directly.
    • macOS installed from the .dmg: there is no system guard. If the app is closed, AI services are reached directly and your requests are not protected.

    The app says so on its own screen, and the device reports it to your IT team.

    Languages and limits¶

    • Languages: the detection model, the ScienceSoft PII Encoder, supports 7 languages: English, Russian, Arabic, Spanish, German, Italian and French. Images in these languages are read on your computer.
    • Images: the app reads one language group at a time (Latin, Cyrillic or Arabic letters). A picture in a different language may be read badly, without a warning. Reading text from blurry or low-quality images is less accurate.
    • Arabic person names are not found yet.

    What is recorded¶

    Protection happens on your computer. The private values that were found are not collected.

    If your computer is connected to a workspace, the workspace's administrators can see what was detected: how many values were found and which types. By default the message is also recorded there, with the private values replaced. So they can read what you wrote, but not the personal data found in it.

    How much is recorded is set by an administrator. The setting is called Data Capture Mode (TraceContent). It has three levels:

    Level What the workspace keeps
    Full (the default) The conversation, with the private values replaced.
    Masked A short excerpt of the text with the private values replaced, with the detection record.
    Metadata Only what was detected. No message text.

    Whose workspace it is matters. Normally it belongs to your company. If your computer is connected to a server run by ScienceSoft, as in a trial, ScienceSoft can see what that workspace records. ScienceSoft can disconnect a computer on request.

    A computer that is not connected to a workspace sends nothing.

    What the AI service receives depends on the mode (see the table above).
