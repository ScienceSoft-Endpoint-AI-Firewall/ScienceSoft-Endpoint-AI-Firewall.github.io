    Roll out the agent to your computers¶

    The agent is the small program that runs on each employee's computer. It checks requests to AI tools and applies the policy you set on the server. This part of the guide shows how to install it on many computers at once, and how to check that it joined your workspace.

    Install the server first. You need its address and the device enrolment key.

    What you need¶

    You need Where it comes from
    The installer AI-Firewall-<version>-x64.exe for Windows and AI-Firewall-<version>-arm64.pkg for macOS. ScienceSoft provides them.
    The server address The public address you gave to setup, for example https://ai-firewall.example.com. It must be https://.
    The device enrolment key Shown by server setup in credentials.txt. You can also make a new one in the admin portal: open Tenants, select your workspace, open the Tokens tab and choose Mint token. The portal shows a new key only once, so copy it at once. Later it shows only a short hash.
    A way to deploy software Microsoft Intune, Jamf, a Group Policy startup script, or any tool that can run an installer as administrator.

    Supported computers¶

    System Supported
    Windows 10 and Windows 11, 64-bit Intel or AMD Yes
    macOS on Apple silicon (M1 or newer) Yes
    macOS on Intel Macs No
    Linux No

    These are the lowest versions of the platform that the app is built on: Windows 10, and macOS 13 (Ventura) or later. ScienceSoft has tested the agent on Windows 11 and on current macOS releases. Windows on ARM computers run the 64-bit Intel build under emulation. That has been tested only in a virtual machine.

    The enrolment key¶

    The key joins a computer to your workspace. It is one key for the whole organisation. When a computer joins, it gets its own credential and stores it in the system keychain. The shared key is not used again by that computer.

    • Anyone who has the key can join a computer to your workspace. Keep it in a password manager or a secret store. Do not put it in a ticket, a chat, or a script on a shared drive that everyone can read.
    • Pass it to the installer when you deploy. After the pilot, consider replacing the key (see below).
    • If the key is wrong, the computer does not appear in the portal. It keeps working on its own, with the local default settings. Nothing is blocked, but the policy does not reach it.
    • To replace the key, make a new one in Tenants, your workspace, Tokens, update your deployment, and then revoke the old key. More than one key can be active at once, so there is no gap.
    • A revoked or expired key stops only new joins. Computers that already joined keep working and keep their own credential. A computer that is reinstalled or enrolled again needs a key that is still active. A computer that tries a revoked key appears under Join failures in the portal.
    • Installers or scripts that you already built with the old key no longer join computers. Update your deployment. The address and the key are read only when the agent is installed, so reinstall a computer to change them.
    • To stop one computer, revoke that device in the portal. Revoking a key does not remove any computer.

    What the installer changes on a computer¶

    Tell your security team about this before the pilot. AI Firewall is installed on your own managed computers, to check traffic to AI services.

    On Windows:

    • Installs the app in C:\Program Files\AI Firewall. The folder is locked, so a standard user cannot change it.
    • Creates a certificate for this computer (called "AI Firewall Local CA") and adds it to the computer's trusted root certificates. The private key stays on the computer.
    • Sets a computer-wide proxy setting that sends AI traffic to the local firewall, and sets Chrome, Edge and Firefox to use it.
    • Installs protection services and scheduled tasks that restart the app. A standard user cannot stop them.
    • Needs no restart.

    On macOS:

    • Installs the app in /Applications.
    • Creates a certificate for this Mac and trusts it in the System keychain.
    • Installs background services, and sets the automatic proxy setting of every network connection to the local firewall. This replaces an automatic proxy setting that your company already has.

    Network: the agent talks to your server address. It also downloads its detection models and updates. See Network access below.

    Uninstalling removes the certificate and the settings that AI Firewall added. See Windows and macOS.

    Network access¶

    The agent needs outbound HTTPS (port 443) to:

    • Your server address.
    • The update address. This is your server address followed by /updates/generic, unless you set another one with /UPDATE_URL on Windows.
    • huggingface.co, where it downloads its detection models. Hugging Face also serves large files from its own download addresses, under huggingface.co and hf.co. Allow those names too. Test this from a pilot computer on a network that blocks everything by default. The agent checks every model file against a fixed hash after the download.

    The agent opens no inbound connections from the network. It listens only on the computer itself (127.0.0.1).

    What the employee sees¶

    With a silent installation, the employee sees nothing during the installation. The app starts in the tray (the Windows notification area, or the macOS menu bar), and the tray icon shows the protection state. The employee cannot stop protection or remove it. See the User Guide for what the app shows.
