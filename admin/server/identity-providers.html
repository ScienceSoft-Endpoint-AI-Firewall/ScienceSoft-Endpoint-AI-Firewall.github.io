    Single sign-on with your company directory¶

    An identity provider (IdP) lets people sign in to the admin portal with the accounts they already have, for example their Microsoft Entra ID account.

    Preview

    Single sign-on is provided by Keycloak's own identity brokering. ScienceSoft AI Endpoint Firewall does not set it up for you and has no Microsoft-specific settings. You set it up in the Keycloak console. It is offered as a preview: the steps below follow Keycloak and Microsoft documentation, and ScienceSoft has not tested them with every directory setup. Test with a test account before you tell people.

    Creating an identity provider needs the built-in Keycloak administrator account (kcadmin). The personal console account that setup creates cannot do it. For the same reason, the Identity providers option is not shown to a super-admin account by default.

    Why use one¶

    • One account and one password. People do not get a separate portal password, and you do not have to deliver passwords.
    • Central account life. When your organisation disables an employee in the directory, that person can no longer sign in to the portal.
    • Your sign-in rules. Multi-factor sign-in, conditional access and password rules of the IdP apply to the portal.

    The IdP only confirms who the person is. Keycloak still decides what they can do: the role, the workspace group and all-workspace access are set in the ai-firewall realm, in the same way as for local accounts. See Sign-in and roles.

    How single sign-on works¶

    A person opens https://<your-address>/admin. They are sent to the Keycloak sign-in page, choose the IdP, sign in there and return to the portal. Keycloak sits between the portal and the IdP.

    Steps for any provider¶

    1. Add the IdP to the ai-firewall realm only. Never to master.
    2. Choose the alias first, for example entra-id. The alias is part of the redirect address and cannot be changed after you create the provider.

    3. Register Keycloak as an application in the IdP. The redirect address is:

      https://<your-address>/keycloak/realms/ai-firewall/broker/<alias>/endpoint

      Do not copy the redirect address that the Keycloak console shows. The console opens through an SSH tunnel and shows an address that starts with http://127.0.0.1. The IdP and the users' browsers cannot reach it. Take the value from the console and replace the part before /keycloak with your public address.

    4. Create the provider in Keycloak with the client ID and the client secret from the IdP.

    5. Plan how people get access. A person who signs in through the IdP for the first time is created in the ai-firewall realm without a role, so the portal does not work for them yet. The realm can also add new people to its default workspace group (default-tenant). Check the group of each new person, because it may not be the workspace that you want. Either give them the role and the group by hand after the first sign-in, or add mappers that do it automatically. Never map anyone to fleet-operators automatically.
    6. Test with a test account before you tell people: open the portal, choose the IdP, and check that the person sees the right workspace.
    7. Optional: skip the Keycloak page. Set the IdP as the default provider of the Identity Provider Redirector step in the browser authentication flow of the realm. Keep at least one local administrator account for when the IdP is not available.

    Microsoft Entra ID¶

    You can connect Entra ID in two ways. Both use an app registration in Entra ID.

    Built-in Microsoft provider Generic OpenID Connect provider
    Effort Low: client ID, client secret and tenant ID Higher: discovery address, client authentication, scopes, signature checks
    Map Entra groups or app roles to Keycloak Not supported Supported, with mappers
    Limit to your organisation Only if you fill in the tenant ID. An empty field lets any Microsoft account in Built in
    Choose it when People only need to sign in, and you give roles and groups in Keycloak You want Entra groups or app roles to give access

    Option 1. Built-in Microsoft provider¶

    In the Microsoft Entra admin center:

    1. Open App registrations, then New registration.
    2. Enter a name, for example AI Firewall admin portal. For Supported account types, choose Accounts in this organizational directory only.
    3. For Redirect URI, choose the Web platform and enter the redirect address from above. Select Register.
    4. On Overview, copy the Application (client) ID and the Directory (tenant) ID.
    5. Open Certificates & secrets, create a new client secret and copy its Value. Note the expiry date: sign-in stops when the secret expires.
    6. In API permissions, check that the delegated Microsoft Graph permission User.Read is there.

    In the Keycloak console (realm ai-firewall):

    1. Open Identity providers and choose Microsoft.
    2. Fill in Alias, Display name (the text of the button on the sign-in page), Client ID, Client Secret and Tenant ID. Do not leave Tenant ID empty.
    3. Select Add.

    Option 2. Generic OpenID Connect provider¶

    In the Microsoft Entra admin center:

    1. Register the application as in steps 1 to 5 above, with the same redirect address.
    2. Open Token configuration and add the optional claim email to the ID token.
    3. To pass Entra groups, select Add groups claim. To pass app roles, define them in App roles and assign people to them in Enterprise applications.

    In the Keycloak console (realm ai-firewall):

    1. Open Identity providers and choose OpenID Connect v1.0.
    2. Fill in Alias and Display name.
    3. For Discovery endpoint, enter https://login.microsoftonline.com/<tenant-id>/v2.0/.well-known/openid-configuration.
    4. Set Client authentication to Client secret sent as post. Fill in Client ID and Client Secret.
    5. Select Add. Then set Scopes to openid profile email, make sure Validate Signatures and Use JWKS URL are on, and select Save.
    6. If Entra passes groups or app roles, open Mappers and add Claim to Role or Advanced Claim to Group mappers that turn them into the role and the workspace group.

    After you connect¶

    • Without mappers, give each new person the role and the workspace group by hand.
    • Never map Entra groups or roles to fleet-operators automatically.
    • Before the client secret expires, create a new one in Entra ID and update Client Secret in the provider.

    More information¶

    • Keycloak: Server Administration Guide, the sections on identity providers and mappers.
    • Microsoft: Register an application and OpenID Connect on the Microsoft identity platform.
