    Operate and upgrade¶

    All commands run on the server, as the administrator (use sudo).

    Everyday commands¶

    Command What it does
    aifw status Shows whether everything is healthy. Safe to run at any time.
    aifw doctor Looks for problems and explains what it finds.
    aifw security-audit Checks the security settings of the server.
    aifw versions Lists the versions you can upgrade to.
    aifw backup Makes a backup now. See Backup and restore.
    aifw --version Shows the version of the aifw command.

    aifw security-audit checks the safety of the server: the firewall, the SSH settings, file permissions, the license, the sign-in service settings and pending system updates. It changes nothing. aifw doctor runs the machine checks, the health checks and the security checks, and prints one numbered list of findings with a fix beside each. It changes nothing too. Both end with a summary line, and return a non-zero exit code if a requirement is not met.

    Backups¶

    The database holds everything: workspaces, devices, audit history and usage statistics. Back it up and keep the backups away from the server.

    sudo aifw backup
    • It writes a dated copy of both databases and a copy of the settings file (.env) into the backups folder under the install folder. It keeps the last 30 days.
    • Setup also installs a daily timer that runs the backup.
    • If you set AIFW_BACKUP_REMOTE, it copies the database dump only to that place. The copy of the settings file stays on the server. Move it to your backup storage yourself. A database dump alone cannot be restored without it.
    • Some data is not saved by aifw backup: captured data, policy presets and your own TLS certificate.

    The full list, the steps for a complete backup and the restore procedure are on Backup and restore. There is no restore command: restoring is a manual procedure. Read it, and rehearse it on a test server, before you need it.

    Upgrade¶

    sudo aifw versions               # what can I upgrade to?
sudo aifw upgrade --version <version>
sudo aifw status
    • Take a snapshot or a backup first. aifw upgrade also makes a backup before it changes anything, and stops if that backup fails.
    • The database is upgraded automatically. Updates are additive, so a server upgrade does not reject or lose data from computers that already use AI Firewall.
    • After the upgrade, check https://<your-address>/health.
    • aifw upgrade does not apply new sign-in settings. After an upgrade that adds them, run sudo aifw setup once. See aifw commands.

    Roll back¶

    If the new version does not work, go back to the previous one:

    sudo aifw upgrade --version <previous-version>

    There is no separate rollback command. In a terminal the command warns that older software will run against data that the newer version already changed, and asks you to confirm. In a script it refuses. If you must go back, restore the snapshot or the backup that you took before the upgrade.

    Re-running setup¶

    Running aifw setup again is safe. It checks every part of the installation and repairs what has drifted, without touching your data, and offers your previous answers. Use aifw setup --check first to see what would change. Setup does not change the public address, the version or the administrator e-mail of a server that is already set up. It stops and names the setting. To move to a newer version, use aifw upgrade. See Install the server.

    Monitoring¶

    The installation includes Grafana (dashboards) and Prometheus (metrics, kept for 30 days). Neither is on the public address. Prometheus is reachable only inside the server's own network, so you cannot open it from outside.

    • The dashboard "ai-firewall — Production Overview" shows whether the server answers, how long /health takes, the database connections and size, and how many computers are in a degraded protection state.
    • One alert rule ships. It fires when a computer's protection has been degraded for more than 10 minutes: its traffic is sent unprotected or is blocked. Alerts are not sent by e-mail. Add your own alerting if you need a notification.

    Open Grafana¶

    From version 2.2.8, Grafana is reached through an SSH tunnel, in the same way as the Keycloak console. It is published on the server's own loopback address only, never on the network.

    1. On your own computer, open the tunnel and keep it running:

      ssh -N -L 3000:127.0.0.1:3000 <user>@<server>

    2. Open http://127.0.0.1:3000 in your browser. Use exactly that address, with 127.0.0.1, not localhost.

    3. Sign in with your personal account through Keycloak. Only super-admin accounts are accepted. Every other role is refused, because the dashboard shows the computers of every workspace.
    4. In an emergency, you can sign in with the local account admin. Its password is in the settings file as GRAFANA_ADMIN_PASSWORD, and in credentials.txt if you kept it.

    aifw upgrade sets this up on a server that was installed earlier. If its sign-in step fails, the upgrade still finishes. It then prints a warning with the cause and the aifw setup command that completes it. In versions before 2.2.8, Grafana has no port on the server, so this tunnel does not work.
