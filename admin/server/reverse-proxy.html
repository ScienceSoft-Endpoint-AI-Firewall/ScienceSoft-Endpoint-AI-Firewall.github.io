    Reverse proxy¶

    Use this page when your own load balancer or reverse proxy ends HTTPS in front of the server (HTTPS option 3 in Install the server). Set the proxy up before you run setup, and before the first device connects.

    You can use nginx, IIS, HAProxy, or a load balancer from your cloud provider.

    What the proxy must do¶

    Requirement Value
    Public address HTTPS on port 443 for your server's name, with your certificate. HTTPS ends at the proxy
    Where it sends traffic Everything (/) to http://<server-ip>:8090
    Server firewall Port 8090 open only to the proxy's address
    Headers Keep the original Host. Send X-Forwarded-Proto: https and X-Forwarded-Host: <your-name>
    WebSocket Pass the Upgrade and Connection headers through
    Timeouts An idle (read and send) timeout of 600 seconds or more
    Buffering Streamed responses (text/event-stream) must reach the client as they are written, not when the response ends
    Request size Allow request bodies of at least 8 MB. Computers upload audit data in bodies of up to 8 MB. nginx refuses bodies over 1 MB by default

    You do not need to do anything for the sign-in service console. The server refuses it on the public address. Administrators reach it through an SSH tunnel (see Sign-in and roles).

    Why these values¶

    The server keeps long connections open:

    • Every managed computer keeps a stream open, so that a policy change reaches it at once. The server sends a keep-alive signal every 25 seconds.
    • The admin portal keeps streams open for audit records, with a keep-alive every 30 seconds.
    • One stream (the violations stream, for the top administrator role only) has no keep-alive yet.

    Because of the keep-alive signals, a timeout of 60 seconds is enough for most streams. Setup generates 600 seconds, which also covers the stream without a keep-alive. A proxy that buffers responses holds events back, so computers get policy changes late. The server tells the proxy not to buffer its streams (X-Accel-Buffering: no).

    nginx¶

    Setup writes this file for you when you choose your own proxy: <install folder>/proxy-snippets/nginx-server-block.conf. nginx waits only 60 seconds by default, so the two timeout lines are required. The file that setup writes has no client_max_body_size line. Add it, as shown.

    server {
    listen 443 ssl;
    server_name ai-firewall.example.com;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    client_max_body_size 8m;

    location / {
        proxy_pass http://<server-ip>:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host ai-firewall.example.com;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

    nginx obeys the "do not buffer" header from the server, so you do not need another setting.

    IIS with URL Rewrite and ARR¶

    Setup writes <install folder>/proxy-snippets/iis-web.config.

    1. Install the URL Rewrite and Application Request Routing (ARR) modules.

    2. Turn on the ARR proxy and set its timeout to 600 seconds or more. In IIS Manager, open the server node, then Application Request Routing Cache, then Server Proxy Settings. Or run:

      %windir%\system32\inetsrv\appcmd.exe set config -section:system.webServer/proxy /enabled:"True" /timeout:"00:10:00" /commit:apphost

      The server tells proxies not to buffer its event streams, but IIS ARR does not read that header. If computers receive policy changes late, set Response buffer threshold in the same place to 0, then check again. ScienceSoft has not verified this setting on a customer installation.

    3. In the site's URL Rewrite settings, add HTTP_X_FORWARDED_PROTO and HTTP_X_FORWARDED_HOST to the Allowed Server Variables. Without them the rule below fails.

    4. Bind the site to your name on HTTPS port 443 with your certificate, and add this rule:

      <configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="proxy-to-ai-firewall" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://<server-ip>:8090/{R:1}" />
          <serverVariables>
            <set name="HTTP_X_FORWARDED_PROTO" value="https" />
            <set name="HTTP_X_FORWARDED_HOST" value="ai-firewall.example.com" />
          </serverVariables>
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>

    HAProxy¶

    Setup does not write a file for HAProxy. This is the equivalent of the nginx block. HAProxy does not buffer responses and passes WebSocket upgrades by itself. After the upgrade, timeout tunnel applies instead of timeout server.

    frontend aifw_https
    mode http
    bind :443 ssl crt /etc/haproxy/certs/ai-firewall.pem
    timeout client 600s
    http-request set-header X-Forwarded-Proto https
    http-request set-header X-Forwarded-Host ai-firewall.example.com
    default_backend aifw_control_plane

backend aifw_control_plane
    mode http
    timeout server 600s
    timeout tunnel 600s
    option httpchk GET /health
    server cp1 <server-ip>:8090 check

    Check after you configure the proxy¶

    curl -fsS https://ai-firewall.example.com/health

    The answer must be {"status":"ok"}. Use your own name instead of ai-firewall.example.com, and your own server address instead of <server-ip>, everywhere on this page.
