    The installer script: install.sh¶

    install.sh is the first step of installing the ScienceSoft AI Endpoint Firewall server. It prepares an empty Ubuntu server and installs one command, aifw. You then run aifw setup, which installs and configures everything else: the server, the admin portal, the sign-in service, the database, HTTPS and monitoring.

    sudo bash install.sh
sudo aifw setup

    Download¶

    File What it is
    install.sh The installer script
    README.txt The same instructions as on this page, as a text file to keep next to the script
    SHA256SUMS The checksum of install.sh, to check that the file is intact

    You need the registry access name and token from your welcome email to run it. The software cannot be downloaded without them. The script does not contain them.

    The script does not contain the registry access name or token. It contains the address of the software registry, which you can override with AIFW_REGISTRY.

    Before you start¶

    • An Ubuntu server. Ubuntu 24.04 LTS is the tested system. On another system the script prints a note and continues. Intel/AMD (x86_64) and ARM (aarch64) processors are supported.
    • Administrator rights (you run it with sudo).
    • Internet access from the server: to the Ubuntu package archive, to the software registry and, for Let's Encrypt, to the certificate authority.
    • The registry access name and token, and the license file, from your welcome email.
    • The server size and ports from Prerequisites.

    Take a snapshot or backup of the server first.

    How to use it¶

    1. Copy install.sh to the server. If you copied it from a Windows computer, convert the line endings first, or it can fail without a message:

      sed -i 's/\r$//' install.sh

    2. Check that the file is intact. Put install.sh and SHA256SUMS in the same folder. The result must be OK:

      sha256sum -c SHA256SUMS

    3. Run the script as administrator:

      sudo bash install.sh

    4. When asked, enter the registry access name and the access token. The token you type is hidden. They are checked at once.

    5. Wait for the script to finish. It ends with:

      Done. The aifw command is installed:
aifw <version>

Next step:  sudo aifw setup

    6. Check the server, then set it up. See Install the server and the aifw command reference:

      sudo aifw preflight
sudo aifw setup

    What the script does¶

    1. Checks that you run it as administrator.
    2. Notes the operating system. It continues on a system other than Ubuntu 24.04.
    3. Checks the processor type. Anything other than x86_64 or aarch64 stops the script before anything is changed.
    4. Installs Docker Engine and the Docker Compose component if they are missing. Docker comes from the Ubuntu package archive.
    5. Signs in to the software registry with your access name and token, and checks them.
    6. Downloads the installer image for this processor type and takes the aifw command out of it.
    7. Puts aifw at /usr/local/bin/aifw and prints its version.

    It does not set up the server. That is aifw setup.

    The registry sign-in is stored for the administrator account (root) in Docker's settings, so that aifw upgrade can download newer versions later. The access token should be a read-only token.

    Settings¶

    For an unattended installation, give the script its settings as environment variables. All are optional, except the two access values, which the script asks for when they are not set.

    Variable Meaning
    AIFW_REGISTRY_USER The registry access name
    AIFW_REGISTRY_TOKEN The registry access token
    AIFW_VERSION The version of the installer to download. By default: the newest published version
    AIFW_REGISTRY The software registry address (set by default)
    AIFW_REGISTRY_PATH The project in the registry (set by default)

    Example, with no questions asked:

    sudo AIFW_REGISTRY_USER='<name>' AIFW_REGISTRY_TOKEN='<token>' bash install.sh

    A command line is not private

    Other users of the server can see a command line for a moment, and it can stay in the shell history. Prefer the questions on the screen, unless the installation is automated and the secret comes from a secret store.

    To install a specific version:

    sudo AIFW_VERSION=<version> bash install.sh

    Running the script again is safe. It repairs a damaged aifw command. It downloads the newest published version unless you set AIFW_VERSION, so on a server that already works set AIFW_VERSION to the version it runs, or use aifw upgrade instead.

    If something goes wrong¶

    The script stops with a line that starts with "Problem:".

    The message says What to do
    This installer needs administrator rights Run it with sudo: sudo bash install.sh
    The software is published for Intel/AMD (x86_64) and ARM (aarch64) servers The server has another processor type. Use a supported server
    Another program is installing software right now Often the automatic security updater, just after boot. Wait a minute and run the script again
    This server could not reach the Ubuntu package archive Check the internet access and proxy settings of the server
    Both the access name and the token are needed Both are in your welcome email. Ask your ScienceSoft contact if you cannot find them
    The registry did not accept the access token Check for typing mistakes. If it still fails, ask for a new token
    Could not download the installer image Check the internet access of the server to the software registry
    This version was not published for this machine There is no build for this processor type. Ask your ScienceSoft contact, or use an Intel/AMD server
    Could not write the aifw command The disk is full or read-only. Check it with df -h /usr/local/bin
    Docker is installed but not running Start it with systemctl start docker

    After you fix the cause, run the script again. For problems with setup, see Troubleshooting.

    Security notes¶

    • Read the script before you run it as administrator. It is a short, plain shell script.
    • Download it only from this site or from your welcome email, and check the checksum.
    • Keep the access token secret. Do not put it into tickets or chats.
