    Troubleshooting¶

    Start here¶

    sudo aifw status
sudo aifw doctor
docker ps

    aifw status says if the installation is healthy. docker ps shows each container. A container that is restarting or unhealthy is where to look first:

    docker logs <container-name> --tail 200

    install.sh does nothing, or fails with a strange error¶

    The script may have Windows line endings, for example if you copied it from a Windows computer. Convert it and run it again:

    sed -i 's/\r$//' install.sh
bash install.sh

    The installer does not accept the registry access details¶

    • Check that you copied the name and the token completely, without spaces.
    • The server needs internet access to the vendor's container registry.
    • If it still fails, ask your ScienceSoft representative to check that the access is active.

    aifw preflight fails¶

    It says which requirement is not met. Typical causes:

    Message about What to do
    Memory, CPU or disk Add resources. See Prerequisites.
    A port is in use Stop what uses it, or choose another HTTPS option.
    The registry cannot be reached Check the proxy and firewall rules for outgoing traffic.
    systemd The server must use systemd.

    Setup stops at "Start secure web access"¶

    You see this message: "Start secure web access — failed". It is usually one of three things:

    1. The cloud firewall (for example a network security group) does not let ports 80 and 443 in.
    2. The DNS name does not point at this server yet.
    3. The certificate is still being issued. Wait a few minutes.

    If you use your own load balancer, it must be fully ready before you run setup. For details, run:

    docker logs ai-firewall-caddy

    Fix the cause. If nothing about the answers has to change, run sudo aifw setup again.

    The server answers, but the sign-in page redirects to the wrong address or shows an error¶

    The single sign-on service may have been set up for a different public address than the one your server uses.

    There is no command that changes the public address of a server that is already set up. Setup refuses a different address.

    • If you have not used the server yet, restore the snapshot that you took before the installation, and run aifw setup again with the right address.
    • If the server is in use (computers are enrolled and people have signed in), do not change the address by hand. Send your ScienceSoft representative the output of sudo aifw status and sudo aifw doctor, and the public address you gave to setup.

    Computers get policy changes late¶

    A proxy that buffers responses, or an idle timeout that is too short, delays the streams. See Reverse proxy.

    I lost credentials.txt¶

    The file is meant to be deleted after you save its contents. Running aifw setup again writes a new credentials.txt from the current settings. Delete it again after you copy what you need.

    • The enrolment key and the emergency token are kept in the settings file /opt/ai-firewall/docker/.env, which only the administrator can read. To read the enrolment key:

      sudo grep '^AIFW_ENROL_TOKEN=' /opt/ai-firewall/docker/.env

    • A forgotten portal password. Another administrator can set a new temporary password in the Keycloak console, or with kcadm.sh. See Sign-in and roles.

    • The temporary password from the sheet works only for the first sign-in. After the administrator has changed it, the sheet shows an old value.

    Getting help¶

    Send your ScienceSoft representative:

    • the output of sudo aifw status;
    • the output of sudo aifw doctor;
    • the last 200 lines of the log of the container that fails.

    Do not send the settings file, credentials.txt, or any token.
