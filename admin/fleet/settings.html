    Settings¶

    The server sends two kinds of instructions to the agents.

    • Settings are values in sections such as firewall, dlp and secrets. You change them on the Config tab of a workspace. This page covers them.
    • Policies say, for each AI service, whether it is allowed, what happens to data, and which uploads are allowed. You change them on the Policies page. See Policies.

    Both reach a computer on its next check. An admin or super-admin can change them. For anyone else the buttons look active, but the server refuses.

    Protection modes¶

    Word on screen What the agent does when it finds sensitive data
    Record only Sends the request unchanged and records what it found. Machine secrets and the organisation's keywords are still replaced
    Replace Swaps each detected value for a placeholder
    Block Does not send the request. A prompt or upload with a detection is stopped as a whole, unless its only findings are the organisation's keywords, which are replaced, or it is a search question that an app sends in a web address, which is replaced and sent

    Block stops the whole request

    In Block, a prompt or file upload with any detection is refused as a whole, and nothing else in it is replaced. The one exception is the organisation's keywords, which are replaced. The employee sees "Request blocked — PII detected" or "File upload blocked — PII detected".

    A new workspace starts in Record only. In the settings the three modes are called monitor, mask and protect.

    The Config tab¶

    Open Settings > Tenants, pick the workspace in Tenant, and open the tab Config. A page has these tabs: Overview, Config, Policy, Result policy, Config history, Groups, Tokens, Audit and Capture.

    The picture shows a test workspace. Names, addresses and IDs are examples.

    • The scope at the top is Tenant wide, Group: name or Device override: name. A group's settings apply to the computers directly in the group, and to those of a child group that inherits from it. See how groups are used.

    • In a group or a device override, a field you do not touch stays Not configured (inherited). Clear Not configured to set a value. For a list, choose whether your values are added to the inherited list, removed from it, or replace it.

    • The list Sections is on the left. Each section is a card with its fields. A Changed badge marks a field you changed, and Clear removes it. Changes stay on the page until you publish them.
    • Validate and Publish appear only after you change a field. Select Validate. When it says "Looks good", Publish (in the bar at the bottom, Publish config) becomes active. It sends the whole config with your changes laid over it. If someone else published meanwhile, you see "Refresh to see the latest config, then re-apply your changes".
    • After publishing, the page shows how many computers acknowledged the new version, for example "Published v7 · all 12 devices acked". It waits up to 60 seconds over the first 200 computers.
    • If you leave the Config or Policy tab with changes that are not saved, a window asks Save your changes? with Cancel, Discard and Save. The Policies page does not ask.

    The server refuses a workspace config bigger than 64 KB (at most 10 levels deep, 64 keys in an object, 1000 items in a list, 8 KB in a string). It checks only the values you changed, so an old value that is wrong does not block an unrelated change.

    For a group or a device override, the server refuses only the newer kinds of mistake: a priority, an inheritance, a merge mode or a list operation that is not valid. Any other value is checked by the same rules as the workspace, but a problem is only a warning. The save goes through, and the console says "The server's checks question these values (devices may not apply them)". Read the warnings: a computer may not apply such a value.

    A few sections must have the object form. For example, write requestTimeout as {"requestTimeoutMs": 60000}, not as 60000; customDlpPatterns as {"patterns": [...]}; userRiskProfiling and evalCapture as {"enabled": ...}. For the workspace the server refuses the bare value. For a group or an override it only warns, and the computer may not apply it. A key the server does not know is stored and ignored by the agent, so a typo is not an error. The server sends a computer only the sections that computer says it supports.

    Settings for one computer¶

    A device override changes settings for one computer without touching the rest.

    1. On the Config tab, choose the scope Device override: name.
    2. Set only the fields you need. Leave the others Not configured (inherited). A new override is in Field by field. If the override carries a Whole block mark, select Switch to field by field. Otherwise every block it sets replaces the inherited block whole.
    3. Select Validate, then Publish config, and check the result in Result policy.
    4. To remove the override, use Clear override on the Override tab of the device page.

    The Override tab of a device is a JSON editor. It shows no server warnings and does not set a merge mode. Use the scope Device override for changes.

    Pause protection on one computer or a group¶

    Use this to take the checks off for a time, for a diagnosis or a compatibility problem.

    1. Choose the scope Device override (or Group).
    2. In the section firewall, clear Not configured for Enabled and switch it off.
    3. To have protection come back by itself, fill Paused Until with a date and time, for example 2026-11-10T18:00:00Z. Without a date, protection stays off until you switch Enabled back on.
    4. Publish. Result policy shows enabled = false, marked "weaker".

    Requests are sent unchecked and unmasked

    While protection is paused, the proxy only passes traffic on. Redirection of traffic stays, but requests to AI services leave the computer without inspection and without replacing anything. A published policy does not change this: it never switches firewall.enabled back on, even in Block. Versions of the app that do not know pausedUntil keep protection off until someone switches it on.

    To only record and not change requests, set the mode Record only in a policy, not here: the mode of an override loses to a published policy. See Where Settings and Policies overlap.

    Result policy¶

    Result policy shows what a computer actually gets, and where each value comes from. Open it under the Tenant, and in Show the result for choose The whole workspace, A group or A device. For a group, the result is worked out as for a computer that is only in that group and has no override. The same result for one computer is on its device page, on the Config tab.

    The block Layers, lowest first lists the layers in order. The tables Parameter | Value | From name the source of each value: Workspace config, Group X (priority N), Parent group X, inherited by Y, Device override or Published policies. A value that a layer weakened is marked "weaker". A value that a published policy overwrote reads "Overwritten by policy …; the config says …".

    When a change reaches a computer¶

    A change to an override, a group or a policy wakes the computers that are waiting for it at once. An app that is connected for pushes picks it up within seconds. An app without that connection, or behind a system proxy service, checks about every 30 seconds, and other agents about every 60 seconds. The times come from reading the product's code, not from a measurement. The server can send a config again at the same version if the result for a computer changed.

    Where Settings and Policies overlap¶

    Settings say how the agent works. Policies say what is allowed and how data is handled. For a few values you can set the same effect in both. A published policy overwrites exactly four values of a computer's settings, and nothing else.

    Setting Policy Overwritten when
    firewall.mode the policy's Mode (Record only, Replace, Block) any policy that applies to the computer sets a mode. Block becomes protect
    dlp.enabledTypes the policy's Data types any applicable policy sets data types
    policy.rules the policy's advanced rules always, even when the policies have no rules. The rules of the workspace, a group or an override are dropped
    policyV2 the whole set of policies always. The server computes it for the computer

    The overwrite is only for that value. In firewall, only mode is replaced: bypassDomains, neverRedact, ocrMode and the rest stay as the settings say. In dlp, only enabledTypes is replaced, and modelId stays. Policies for people do not take part in overwriting the mode or the types of data.

    So a mode in a device override loses to a published policy, even when the override is stricter. To set the mode or the data types for everyone, for a group or for one computer, set them in a policy. To make a value from the settings count, take the mode and the data types out of every policy that applies to the computer. The console says "Published policies (vN) are layered last" on the device's Config tab. The Override tab does not warn.

    Some pairs look alike but are not linked. Both values reach the agent and work on their own.

    Settings Policy The difference
    neverRedact, customExclusions Keywords The first are values that are never replaced. The second are words that are always replaced
    secrets.classes the data types preset Credentials Secrets are a section of their own
    bypassDomains, extraTargetDomains Access of a service The first says which hosts are inspected. The second says whether a service is allowed
    resilience Access: Block The first says what happens when the proxy stops. The second forbids a service

    Apps older than the policy version of the product get a smaller result: the mode, the data types, the rules and the block of a service by whole host. They do not get modes per service, upload controls, keywords or the controls of coding agents.

    Config history¶

    The tab Config history shows every version of the config, who made it and when. Choose a Scope: Workspace config, Groups, Device overrides or Policies (by the name of the policy).

    Select a version to compare it with the one before. Download CSV and Download JSON export the list. Rollback to this version makes a new version that is identical to the old one, and you can add a comment that goes into the admin log. After a rollback the page opens the Config tab.

    Scope Roll back?
    Workspace config Yes
    Groups Yes. The history of a deleted group is read-only
    Device overrides Yes. A roll back to the version "no override" deletes the override
    Policies No, view only. Change the policy on the Policies page and publish

    History is kept without a time limit. For a group, an override or a set of policies saved before this feature, the first change records the earlier state as version 1, with the author "not recorded", so you can roll back to it.

    What each setting does on this product¶

    The editor shows more sections than the agent uses. These are the ones this product reads.

    Section What it sets
    firewall mode (the three modes above), enabled, pausedUntil (pauses protection until a time, then it comes back by itself), neverRedact and customExclusions (text never to replace), bypassDomains, extraTargetDomains, pseudonymize, and for pictures ocrMode and ocrLanguage
    dlp modelId (the detection model) and enabledTypes (the types of data to look for)
    recognizers Which countries' national identifiers computers look for. See below
    customDlpPatterns Your own patterns. See below
    dlpThresholds How sure a detector must be, per type
    requestTimeout How long to wait for an AI service
    secrets Secret scanning: enabled and the kinds to look for
    documentInspection How deep to look inside files and archives
    traceContent What the workspace keeps of conversations: metadata, masked or full. See What the workspace records
    auditIdentity Whether audit records name the person. See What the workspace records
    capture The counters and request details the agents send. See What the workspace records
    runtimeLogs Agent log lines for the device page: enabled, minLevel, sampleRate
    resilience What AI traffic does when protection is down: "Block AI traffic until protection is back" or "Let AI traffic through, unprotected"
    steering, toolSteering Which command-line AI tools are sent through protection
    aiClientCatalog Extra AI apps to recognise
    updater autoUpdateEnabled, forceVersion
    policy Advanced rules. See Policy rules

    These sections are for another product and do nothing here: userRiskProfiling, evalCapture and deviceKeyRotation. Do not turn on learningMode or evalCapture expecting a feature: current agents record no prompt because of them. The setting updater.silentInstall also does nothing: every update still asks the person to confirm. Inside firewall, the fields otelEndpoint, port, targetDomains and learningMode are ignored.

    recognizers. The field countries names the countries whose national identifiers (for example tax and ID numbers) computers look for. If the section is absent, computers look for every country. Only identifier checks are narrowed: names, e-mail addresses, phone numbers, card numbers and bank accounts are always checked. The help text says to "Leave empty to look for every country", but the server refuses an empty list. To look for every country, remove the section.

    Files that cannot be read are allowed by default

    documentInspection.uninspectableAction is allow unless you set it, so a file that the agent cannot read is sent on. Set it to block yourself if you want such files to be refused.

    What a computer does before it reaches the server¶

    After a restart, before its first check, a computer remembers only the protection mode the organisation set last. Everything else the organisation set starts again from the built-in values until the first check: the lists of text never to replace, the types of data, the policy rules, the thresholds and the secrets setting. A pause lapses too, so a paused computer protects again until it checks in. A computer with no server at all uses the built-in values: Record only and 20 types of data. A workspace starts with 17. Those two lists differ a little.

    Policy rules¶

    Policy rules are advanced rules for a workspace or a group. Open the tab Policy.

    A rule has an id, a priority (lower runs first), an action (pass, mask, block, reroute or log), a reason shown to the person on a block, and conditions. The first rule that matches wins. Evaluate tests rules in the browser. Revert and Save rules appear after a change.

    When the workspace has published policies, the rules on the Whole workspace scope are the organisation default's advanced rules. Save rules then publishes a new version of the policies, and the page says "Published policies v8 · 3 rules". A policy of a group or a computer that sets its own rules gets those instead. A blocked service or upload is refused before any rule runs. If the page was loaded from an older version, saving is refused: "Nothing was saved: this tenant has published policies (v8), and this page did not load its rules from them. Refresh, then make your change again."

    On the Config tab, the policy section shows a summary with the button Open policy builder, and Edit as JSON.

    Part of a rule What a computer does
    block, mask Works in Replace and Block. In Record only the rule only records
    pass Changes nothing
    log Sends the request unchanged, even in Replace and Block. The name suggests logging, but the original text leaves the computer
    reroute Not carried out. The rule acts as if it had not matched, and the rules below it are not checked. The portal says so
    Conditions on domain, types of data and minimum size Work
    Conditions on departments and file types Never match. The portal marks them "Not enforced on devices yet"
    The switch Audit-capture on match Ignored. Nothing extra is recorded

    A rule that is malformed makes the computer refuse the whole push and keep the last good rules. A group's rules saved here, while policies are published, can be overwritten by the published set, and the page shows a notice.

    Text that is never replaced¶

    neverRedact lists text that stays in a request even when a detector matches it. Put one value on each line. *.example.com keeps a whole domain, and any other * is refused. customExclusions is a second list that works the same way. Only the organisation can set these lists. A person cannot add to them on their own computer.

    extraTargetDomains adds AI services to inspect. bypassDomains turns inspection off for a service.

    Custom patterns¶

    customDlpPatterns lets you add your own patterns, for example an internal project code. Select + Add pattern. A pattern has an id, a name, a type (a prefix of your own that must not equal a built-in type), the pattern itself, flags and a severity from 0 to 100. Use Test against fixture to try it on sample text.

    The portal refuses a pattern that does not compile. It also flags back-references, look-ahead and look-behind, because the agent's pattern engine does not support them. A pattern can be 500 characters long. A bad pattern is skipped and logged. A new list replaces the old, and an empty list clears it.
